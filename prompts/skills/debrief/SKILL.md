# Session 知識回收

## 任務

回顧本次對話中的所有討論，識別值得沉澱到知識庫的洞見，列出建議清單讓使用者確認後寫入。

## 步驟

### Phase 1：回顧對話

掃描本次對話中的所有討論內容，識別以下類型的可沉澱知識：

| 類型 | 範例 | 沉澱方式 |
|:--|:--|:--|
| **結論** | 「方法 A 比 B 更適合因為 X」 | 更新到相關概念筆記的「我的理解」段落 |
| **否定性發現** | 「X 方法不適用因為 Y」 | 記錄到相關筆記的「待解決問題」或「說明」段落 |
| **跨概念連結** | 「發現 A 和 B 的關聯」 | 在兩篇筆記的「相關筆記」中互相連結 |
| **新概念** | 討論中提到的未建檔概念 | 建議建立新概念筆記 |
| **修正** | 「原來 X 不是那樣，而是...」 | 更新現有筆記的錯誤內容 |
| **研究想法** | 「如果把 X 和 Y 結合可能可以...」 | 加入相關筆記的「待解決問題」或研究想法 MOC |

### Phase 2：生成建議清單

輸出結構化清單：

```
## 本次對話可沉澱的洞見

### 更新現有筆記
1. [[筆記名]] — 加入「[具體內容摘要]」到 [段落名]
2. [[筆記名]] — 在「相關筆記」加入 [[連結目標]]
3. ...

### 建議新建筆記
1. 「概念名」— [為什麼值得建檔]
2. ...

### 修正
1. [[筆記名]] — [修正內容]

共 N 項建議。要全部執行、選擇部分、還是跳過？
```

### Phase 3：執行寫入

使用者確認後：
1. 逐一更新指定筆記
2. 建立使用者同意的新筆記
3. 執行修正
4. 若建立了新概念筆記，提醒是否需要 rescan

## 注意事項

- 不要把對話中的閒聊或操作指令當作知識
- 只提取有長期價值的洞見——一個月後回看仍有意義的內容
- 偏好更新現有筆記而非建立新筆記（減少碎片化）
- 每項建議都標明來源（「這是我們討論 X 時得出的結論」）
- 若本次對話沒有值得沉澱的內容，直接說明，不要硬湊
