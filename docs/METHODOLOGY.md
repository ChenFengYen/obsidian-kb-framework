# 方法論：AI 引導式知識庫建設

## LYT（Linking Your Thinking）基礎

本框架基於 Nick Milo 的 LYT 方法論。核心理念：

**知識應作為相互連結的網路運作，而非階層式資料夾。**

### 三層導航結構

```
Home（首頁）
  ↓
MOCs（內容地圖）
  ↓
Notes（概念筆記）
```

- **Home**：知識系統入口，連結所有 MOC
- **MOC（Map of Content）**：某個領域的思考地圖，不是連結清單
- **概念筆記**：原子化的知識單元，一個概念一份筆記

### 連結哲學

連結分兩層：
- **自動連結**（腳本生成）：基礎可發現性，每概念只連結首次出現
- **思考連結**（人工/AI 建立）：MOC 中的敘述性連結、概念筆記的「相關筆記」— 真正的價值所在

## 兩路徑策略

知識庫建設有兩條互補路徑：

| | 批量路徑 (Pipeline) | 問題驅動路徑 (Collaboration) |
|:--|:--|:--|
| **驅動力** | 腳本掃描薄弱筆記 | 使用者提問 |
| **目標等級** | basic（10-15 行） | rich（≥30 行） |
| **適用階段** | 早期覆蓋、快速打底 | 長期深化、精準補強 |
| **人機互動** | 事後審核 | 即時共創 |
| **標記** | `AI-ENRICHED` | `CO-CREATED` |

**分工**：批量路徑打底（廣度），問題驅動深化（深度）。

## 筆記充實度分級

| 等級 | 內容行數 | 說明 |
|:--|:--|:--|
| stub | 0–3 | 僅標題或一句定義 |
| thin | 4–9 | 基本定義但缺乏結構 |
| basic | 10–29 | 有結構，可搜尋可引用 |
| rich | ≥30 | 完整：定義、概念、應用、連結、問題 |

## 知識回收機制

對話中產生的知識不應遺失在聊天記錄中。框架提供三種回收策略：

1. **debrief**：僅 session 結束時回顧洞見
2. **inline+debrief**：對話中即時標示 + 結束回顧（推薦）
3. **journal+debrief**：建立探索日誌 + 結束回顧

## 多源驗證原則

概念筆記的內容應有至少兩個不同來源支持：
- **共識性知識**（如教科書內容）→ 可直接寫入
- **單一來源的發現** → 標註來源並註明驗證狀態
